# MRZ Extraction — Development Handoff

Last updated: 2026-08-14

## Objective

The Flask check-in site (Lotto235, Railway) extracts MRZ (machine-readable zone)
data from uploaded passport/ID photos and PDFs during guest check-in. The goal is
**maximum extraction accuracy first, then minimal server resources** — and strongly
**server-side** processing (no client-side OCR). Uploaded ID images are PII and are
processed **in memory only, never stored** — keep this property.

## Current Stack (in production code)

All in `/home/lucanegri/Apt_Website/app/services/`:

- **`mrz_cnn.py`** — char-level CNN OCR (onnxruntime, no system binary).
  - Model: `app/services/models/mrz-cnn.onnx` (916KB, 20×20 input → 37 symbols
    `0-9 A-Z <`) + `mrz-cnn.json` symbol table. Source: alsenet-labs/mrz-scanner
    (packages/mrz-ocr).
  - Lazy singleton ONNX session (`CPUExecutionProvider`), `available()` guard,
    `cnn_ocr_lines(region)` returns line strings.
  - Segmentation: Otsu → connected components → aspect-ratio filter 0.3..3.0 →
    Y-clustering (`line_threshold = height/6`) → keep last 3 lines with ≥5 chars.
  - Tested read on clean OCR-B renders: passport line2 `YB4137770<0ITA9302042M2902114`
    read 100% correctly.
- **`mrz_extractor.py`** — orchestration + parser.
  - `extract_mrz(data)` → `MrzResult(ok, error, raw_lines, engine, document_type,
    document_number, surname, given_names, nationality, birth_date, sex,
    expiry_date, country)`.
  - **Crop fix (2026-08-14):** `_crop_mrz_region` gap-merge threshold raised from
    `0.8×` to `1.5×` median line height. Old logic under-cropped to only the last
    MRZ line when line spacing ≥1.1× line height, which broke both engines on
    full-page renders. Over-cropping is safe: parser scans bottom-up and the CNN
    keeps only the last 3 lines.
  - **Dual-engine:** CNN runs first; tesseract (psm 6 → 11) runs as fallback AND
    confirmation; winner recorded in `result.engine` (`cnn`/`tesseract`).
  - Parser: TD3 (2×44, `P<...`), TD1 (3×30, `I<...`); validates country codes,
    dates, names; `_digits`/`_letters` cleanup maps OCR confusions (O→0, I→1,
    B→8, S→5 and reverse).
  - PDFs rendered via PyMuPDF (`fitz`) at 200 DPI.
  - `_pick_ocr_lang()` prefers `ocrb_int` traineddata, falls back to `eng`.

OCR problem). No engine rotates the image first.

## MRZScanner (DocsaidLab) Evaluation — NOT adopted

Prototyped in Docker (`mrzproto` image). Verdict: **not worth the cost**.

- Accuracy: 85%/54% on clean valid renders (char-CNN reads them 100%);
  **0% on 90/180/270° rotation** (not rotation-invariant despite marketing);
  only mild skew (≤15°) works. Its only edge over the current stack is skew —
  which the tesseract fallback already handles.
- Cost: ~70MB ONNX models + 33.7MB CJK font (downloaded at import time from
  Google Drive — must be baked into the image or Railway breaks); dep chain:
  `onnxruntime_gpu` (must override to CPU), full `opencv-python` + libGL,
  matplotlib, shapely, PyTurboJPEG `<2` (needs libturbojpeg), `capybara==0.12.0`
  pinned. ~350ms/image vs near-instant CNN.
- Setup gotchas found: Debian trixie package is `libturbojpeg0` (not
  `libturbojpeg`); `PyTurboJPEG<2` (v2 needs libjpeg-turbo 3.0);
  `capybara-docsaid==0.12.0` (v1.0.1 broke `capybara.Backend`);
  `do_center_crop=False` is required (center crop destroys full-page scans);
  model file_ids + ckpt dirs in `mrzscanner/det|rec/infer.py`.
- **Revisit only if:** a real phone photo demonstrates a clear win over the
  current stack. Synthetic renders cannot measure this (MRZScanner is trained on
  real photos).

Rejected alternatives: **fastmrz** (tesseract+ONNX wrapper, AGPL-3.0, no real
improvement), **document-mrz-scanner** (Node.js only), **RapidOCR** (general
PaddleOCR, not MRZ-specialized).

## Environment Quirks

- Local: Python 3.12.3, `pip3 install --user --break-system-packages`.
  `onnxruntime` installed locally; capybara/MRZScanner can't run locally (needs
  libturbojpeg, no sudo) — Docker only.
- Local tesseract tests need `TESSDATA_PREFIX=/tmp/opencode/tessdata`; system
  tessdata only has `eng`/`osd` locally. Docker image has `ocrb_int` installed
  at `/usr/share/tesseract-ocr/5/tessdata/`.
- Railway uses the `python:3.13-slim` `Dockerfile` (Nixpacks not honored).
  `Pillow` must stay ≥ 11.0.0; `onnxruntime` is NOT yet in `requirements.txt`
  (add when this ships). Tesseract already installed in the Docker image.
